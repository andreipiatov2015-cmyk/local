# Что добавить на сервер

Приложение работает с сервером по простому HTTP API в формате JSON.
Нужно реализовать **2 адреса** (третий — по желанию). Авторизации нет, только чтение.

Готовый рабочий пример лежит в папке `server/` (Python, без внешних библиотек) —
его можно запустить как есть или переписать на язык вашей программы.

---

## 1. `GET /api/info` — информация о сервере

Нужен для проверки связи и чтобы показать имя сервера в приложении.

```json
{
  "name": "Склад №1",
  "version": "1.0",
  "updated_at": "2026-11-10T00:15:00+07:00"
}
```

| Поле         | Тип    | Обязательно | Описание                                   |
|--------------|--------|-------------|--------------------------------------------|
| `name`       | строка | да          | Название, отображается в шапке приложения  |
| `version`    | строка | нет         | Версия API/программы                       |
| `updated_at` | строка | нет         | Когда данные последний раз менялись        |

## 2. `GET /api/items` — все данные

Главный метод. Приложение запрашивает его при открытии и потом каждые N секунд
(по умолчанию 30, меняется в настройках), а также по кнопке «Обновить».

```json
{
  "updated_at": "2026-11-10T00:15:00+07:00",
  "items": [
    {
      "id": "1",
      "title": "Болт М8×40",
      "subtitle": "Крепёж",
      "updated_at": "2026-11-09T18:20:00+07:00",
      "fields": {
        "Артикул": "BM8-40",
        "Остаток": 1250,
        "Цена, ₽": 4.5,
        "Ячейка": "A-12"
      }
    }
  ]
}
```

Поля записи:

| Поле         | Тип                 | Обязательно | Описание                                        |
|--------------|---------------------|-------------|-------------------------------------------------|
| `id`         | строка или число    | да          | Уникальный идентификатор                         |
| `title`      | строка              | да          | Заголовок в списке                              |
| `subtitle`   | строка              | нет         | Вторая строка в списке                          |
| `updated_at` | строка              | нет         | Когда запись менялась (любой читаемый формат)   |
| `fields`     | объект              | нет         | Любые поля «название → значение», показываются в карточке записи в том же порядке |

Значения в `fields` могут быть строками, числами, `true/false` или `null`
(в приложении `null` показывается как «—»). Имена полей — что угодно, на русском тоже можно.

> Структура специально универсальная: сервер сам решает, какие данные отдавать.
> Чтобы показать новое поле, достаточно добавить его в `fields` на сервере —
> обновлять приложение не нужно.

## 3. `GET /api/items/{id}` — одна запись (необязательно)

Возвращает один объект записи в том же формате или `404`. Приложению сейчас не нужен,
но удобен для проверки и будущих функций.

---

## Требования к ответам

1. Заголовок `Content-Type: application/json; charset=utf-8`, текст в **UTF-8**.
2. Код ответа `200` при успехе. При ошибке — `4xx/5xx`, приложение покажет
   «Сервер ответил: код …» и оставит на экране последние полученные данные.
3. Сервер должен слушать сетевой интерфейс, а не только `localhost`
   (например `0.0.0.0:8000`), и порт должен быть открыт в брандмауэре.
4. Обычный `http://` поддерживается (для локальной сети). Если сервер доступен
   из интернета — лучше поставить `https://` (например, через nginx + Let's Encrypt).
5. Ответ должен приходить быстро: таймаут в приложении — 10 с на подключение и 15 с на чтение.
   Если записей очень много (десятки тысяч) — напишите, добавим постраничную загрузку.

## Как проверить сервер без телефона

Откройте в браузере на компьютере из той же сети:

```
http://АДРЕС_СЕРВЕРА:8000/api/info
http://АДРЕС_СЕРВЕРА:8000/api/items
```

Если в браузере видны данные в JSON — приложение тоже их получит.
В приложении в настройках укажите тот же адрес: `http://АДРЕС_СЕРВЕРА:8000`.

## Подключение: локально и удалённо

На главном экране приложения вводятся **IP-адрес и порт**, затем «Подключиться».
Последние адреса запоминаются — переключаться между ними можно одним нажатием.

| Кто                    | IP в приложении                                  | Порт                    |
|------------------------|--------------------------------------------------|-------------------------|
| Пользователь в той же сети | внутренний IP сервера, например `192.168.1.10` | порт сервера, `8000`    |
| Вы удалённо            | внешний (белый) IP роутера                        | внешний проброшенный порт |

Чтобы удалённое подключение работало, в роутере нужен **проброс порта**
(Port Forwarding / «Виртуальный сервер»): внешний порт, например `8000`
→ внутренний IP сервера `192.168.1.10`, порт `8000`, протокол TCP.
У сервера в локальной сети лучше закрепить постоянный IP (резервирование DHCP в роутере).
Если внешний IP у провайдера меняется — поможет DDNS, тогда в поле IP можно ввести имя
вида `myhome.keenetic.pro` — приложение принимает и имена.

> ⚠️ Данные открыты без пароля: при пробросе порта их может прочитать любой,
> кто знает IP и порт. Если данные чувствительные — ограничьте в роутере доступ
> к пробросу по вашему IP, используйте VPN (WireGuard на роутере) или скажите,
> добавим в API простой ключ доступа.

## Чек-лист для доработки программы на сервере

- [ ] Отдавать `Content-Type: application/json; charset=utf-8`
- [ ] Слушать `0.0.0.0`, открыть порт в брандмауэре
- [ ] Проверить оба адреса в браузере с другого устройства
